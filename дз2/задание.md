# Семинар 2. Разбор обращения по схеме

Собираем функцию `triage(text)`: она разбирает обращение клиента и возвращает
объект `Ticket`: категорию, срочность, нужен ли человек, цитату, номера
платежей и сумму. Схема проверяет не только форму ответа, но и то, что модель
ничего не выдумала и не потеряла: цитата должна быть дословной, номера
платежей должны быть взяты из текста, и ни один номер из текста не должен
пропасть.

В заготовке шесть мест `# TODO С2`. Три из них преподаватель пишет на экране,
три вы пишете у себя.

## Перед занятием

Подтяните заготовку в свой форк, как написано в README, проверьте, что в
`.env` вписан ключ, и запустите тесты:

```bash
python -m pytest tests/test_s2_triage.py
```

Ожидаемо падает 21 тест из 22: на месте будущей работы стоит
`NotImplementedError`.

## Что пишете вы

| Раунд | Что | Подсказка | Проверка |
|---|---|---|---|
| 1 | `quote_is_verbatim` в `desk/schemas.py` | Устроен так же, как соседний валидатор номеров: исходный текст лежит в `info.context`, сравнивайте через `_norm` | `pytest tests/test_s2_triage.py -k "schema or quote"` |
| 1 | Свой случай в `test_schema_rejects` | Допишите в список параметров испорченный ответ, который схема должна отклонить | тот же тест |
| 2 | `structured` в `desk/structured.py` | Вызов модели, `extract_json`, проверка схемой с контекстом; при ошибке допишите в историю ответ модели и текст ошибки из `_complaint` | `pytest tests/test_s2_triage.py -k structured` |
| 3 | `atriage_many` в `desk/triage.py` | Семафор и `gather`, как в `run_candidate` из первого семинара, и обязательно `return_exceptions=True` | `pytest tests/test_s2_triage.py -k batch` |

Номера платежей в `desk/schemas.py`, `extract_json` и `build_messages`
преподаватель пишет на экране. Если отстали, перенесите их с экрана, чтобы
дальше работать вместе со всеми.

## Команды занятия

Разобрать своё обращение, например то, которым вы пытаетесь сломать разбор:

```bash
python 2_ticket.py "текст обращения"
```

Разобрать обращения из набора и сравнить с эталоном:

```bash
python 2_ticket.py T-017 T-025 T-085 T-011 T-031 T-001 T-028 T-062 T-068 T-086
```

Первые пять обращений спорные, модель расходится на них с эталоном. Остальные
пять контрольные, и правка постановки не должна их сломать.

Замер на 30 обращениях, около двух минут из-за лимита 10 запросов в минуту:

```bash
python -m desk.triage --split dev --n 30
```

В конце вывода замер печатает взвешенные токены на обращение и список
расхождений с эталоном.
